# 可解释的国际象棋复盘教练（MVP）

一个**本地运行**的网页应用：复盘你自己的对局，告诉你**反复犯的是哪一类错误**，而且每一条结论
都能追溯到 Stockfish 的原始输出或者确定性的棋盘事实。

一句话原则：

> Stockfish 判断好坏，确定性分析提取可核实的事实，AI 只负责把这些事实讲成人话。

大语言模型**永远不会**自己去评估局面。整个代码库里不存在 `FEN → LLM → 棋力判断` 这条路径。

```
PGN ──▶ python-chess 重放 ──▶ 两遍 Stockfish 分析 ──▶ 结构化证据对象
                                                        │
                          ┌─────────────────────────────┤
                          ▼                             ▼
                  确定性概念检测器                 决策失误分类
                          │                             │
                          └──────────────┬──────────────┘
                                         ▼
                       AI 解释（受约束、会校验） ── 或者 ── 规则模板
                                         ▼
                        SQLite：对局、失误事件、个人档案
```

## 1. 三步跑起来

在项目根目录（`chess/`）打开终端：

```bash
# 第一步：安装（只需要做一次）
./scripts/setup.sh

# 第二步：启动（前端 + 后端一起跑起来）
./scripts/dev.sh

# 第三步：浏览器打开
# http://localhost:3000
```

`setup.sh` 会自动完成：创建 Python 虚拟环境 → 安装后端依赖 → 下载 Stockfish 19 →
安装前端依赖。已经装过的步骤会跳过，可以重复运行。

`dev.sh` 会在同一个终端里同时启动两个服务，**按 Ctrl-C 一起结束**。启动成功后它会打印：

```
================================================================
  界面地址：   http://localhost:3000
  接口地址：   http://127.0.0.1:8000/api/health
  停止服务：   在这个终端按 Ctrl-C
================================================================
```

### 如果你想手动分步执行

```bash
# 1) Python 环境
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt

# 2) Stockfish 19（下载到 backend/engine/bin/，约 100MB）
.venv/bin/python backend/scripts/install_stockfish.py

# 3) 前端依赖
cd frontend && npm install && cd ..

# 4) 可选配置（不配也能用）
cp .env.example .env

# 5) 启动后端（终端 A）
cd backend && ../.venv/bin/python -m uvicorn api.main:app --port 8000

# 6) 启动前端（终端 B）
cd frontend && npm run dev        # 打开了 http://localhost:3000
```

> 如果你的机器上已经有 Stockfish，可以跳过第 2 步，改成在 `.env` 里写
> `STOCKFISH_PATH=/opt/homebrew/bin/stockfish`（Homebrew 安装的路径）。

## 2. 怎么用

1. **导入对局**：在首页把 PGN 粘贴到文本框，或者点「上传 PGN 文件」。不知道去哪找 PGN？
   chess.com / lichess 的对局页面都有「下载 PGN」或「复制 PGN」。
   点「填入示例」可以先拿一盘样例棋试一下。
2. **选择你执哪一方**：默认「自动判断」（会参考你以前导入过的棋手名）。如果判断不出来，
   手动选「白方」或「黑方」即可。
3. **点「开始分析」**：按钮下方会出现进度条，40 步左右的对局一般 10–30 秒。
   分析完成后会自动跳到复盘页面。
4. **看复盘页**：
   * 左边是棋盘，工具栏有三排按钮：
     * `⏮ ◀ 上一步 / 下一步 ▶ ⏭` —— 逐步查看整盘棋（键盘 `←` `→`）；
     * `⇤ 上一个关键局面 / 下一个关键局面 ⇥` —— **一键在关键局面之间跳转**，
       不用自己数着法（键盘 `Shift + ←` / `Shift + →`）；
     * 下面一行会显示「关键局面 2 / 5」，告诉你当前位置和总数。
   * 棋盘上的**蓝色箭头**是引擎推荐的走法，**红色箭头**是实战走法。
     只有当你站在「你当时面对的局面」上时才会画箭头——因为引擎推荐的是**走这一步之前**的着法，
     棋子落下之后再画就没有意义了。棋盘移开时这一行会提示「棋盘已移开，点卡片可跳回」，
     展开的面板里也有「把棋盘移回这个局面」按钮。
   * 右边是着法列表，每个着法旁边的小圆点颜色表示质量，关键着法带「关键」标签；
     鼠标停在任意着法上会显示引擎推荐（例如「引擎推荐 Rdd1」）。
   * **每一手都能看到引擎推荐。** 棋盘停在任何一个局面时，左侧信息卡都会显示
     「实战走法 vs 引擎推荐」：蓝色箭头是引擎推荐，红色箭头是实战走法（两者相同就只画一个）。
     你可以在任意位置按「下一步」浏览全盘，随时看到引擎当时想要什么。
     **只有关键局面才生成 AI 解释**——其余着法只给引擎推荐，界面上会明确说明这一点。
   * 下面是「**这盘棋真正值得复盘的 N 个局面**」。点卡片会做两件事：把棋盘跳到那个**决策点**
     （也就是你当时面对的、还没走错的那个局面），并**在该卡片正下方展开**详细内容——
     不用再滚到页面底部：
     * **引擎证据**（蓝色边框）：评估、WDL、期望得分、推荐走法、PV 线路、其他候选；
     * **AI 教练解释**（黄色边框）：发生了什么、为什么重要、下次怎么想、可复用的经验。
5. **把引擎的后续走一遍**（不用自己在脑子里推演）：
   棋盘下方（就在棋盘旁边）点「**▶ 演示后续走法**」，棋盘就进入线路演示模式——
   从**当前这个局面**出发，一步一步走完引擎的后续，走完点「← 返回实战对局」回到真实棋局。

   **任何局面都能用**，不限于关键局面：你现在看的是哪一步，演示的就是哪一步之后的后续。

   * 两条线路可以随时切换：
     * **引擎推荐线路** —— 如果当时走对了会怎样；
     * **实战线路** —— 你实际走的这步之后，引擎会怎么惩罚你。
   * 操作：`▶ 自动播放`（每 0.9 秒一步）、`⏮ ◀ ▶ ⏭`、直接点某个着法跳到那一步；
   * 键盘：线路模式下 `←` `→` 走的是线路（不是实战棋局），`Esc` 返回实战；
   * 棋盘上**红框高亮**是刚走的那一步，**蓝色箭头**是线路的下一步；
   * 每一步的回合号、走的哪一方、接下来走什么都会实时显示；
   * 移动棋盘（上一步/下一步/点着法列表）会自动退出演示模式，避免把某一步的线路画到别的局面上。
5. **看个人档案**：顶部导航「个人档案」。分析多盘棋之后，这里会显示你反复犯的错误类型、
   按阶段的分布、以及最近几盘的趋势。样本少的时候它会明确写「目前观察到」，不会下结论。

### 关于 AI 解释

没有配置 `DEEPSEEK_API_KEY` 时，应用**完全可以正常使用**，只是解释文字来自确定性的中文模板，
界面上会标注「规则模板说明（未使用 AI）」。想要 AI 版本的解释，在 `.env` 里填上：

```
DEEPSEEK_API_KEY=sk-你的密钥
```

然后重启后端。API Key 只保存在后端进程里，前端代码和浏览器永远看不到它。

## 3. 配置 DeepSeek API Key（详细步骤）

### 先想清楚：你需要它吗

**不需要也能完整使用。** 不配 Key 时，应用会：

* 照常跑 Stockfish 分析、找关键局面、检测概念、分类失误；
* 用**确定性中文模板**生成解释（内容来自引擎证据，措辞是固定的）；
* 在界面上把这段文字标记为「规则模板说明（未使用 AI）」。

配了 Key 之后，同样的证据会交给大模型组织成更自然、更贴合具体局面的中文，并在界面上标记为
「AI 教练解释」。**两者的引擎证据完全相同**——AI 只是把事实说得更好懂，不会改变任何判断。

想配的话，去 <https://platform.deepseek.com> 注册 → 创建 API Key（形如 `sk-xxxxxxxx`）→
在「充值」页面充一点钱（一次几块钱就够复盘很多盘棋）。

### 第一步：创建 `.env` 文件

在**项目根目录**（也就是有 `README.md` 和 `scripts/` 的那一层）执行：

```bash
cp .env.example .env
```

然后编辑 `.env`，找到这一行并填入你的密钥：

```
DEEPSEEK_API_KEY=sk-你的真实密钥
```

`.env` 放在哪、能不能放别处：

| 文件位置 | 是否生效 | 说明 |
| --- | --- | --- |
| `chess/.env` | ✅ | 推荐，和 `README.md` 同级 |
| `chess/backend/.env` | ✅ | 也支持；**两个文件同时存在时，这个优先级更高** |
| 其它位置 | ❌ | 不会被读取 |

`.env` 已经在 `.gitignore` 里，不会被提交到仓库。

### 第二步：格式要求（这一节最容易出错）

`.env` 是**一行一个** `键=值`，不要写成 shell 脚本：

```ini
# ✅ 正确
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
DEEPSEEK_MODEL=deepseek-chat
```

常见的错误写法：

```ini
# ❌ 不要加 export（这是 shell 语法，不是 .env 语法）
export DEEPSEEK_API_KEY=sk-xxx

# ❌ 不要加分号注释（会被当成值的一部分）
DEEPSEEK_API_KEY=sk-xxx  ; 我的密钥

# ❌ 不要在值两边加引号（多数情况能解析，但复制时容易带进多余字符）
DEEPSEEK_API_KEY="sk-xxx"

# ❌ 不要粘成两行（密钥中间不能有换行或空格）
DEEPSEEK_API_KEY=sk-abc
def123456

# ❌ 文件名不要变成 .env.txt（macOS 的文本编辑容易自动加后缀）
```

判断标准很简单：`=` 右边到行尾（不含首尾空白）就是密钥本身，中间不能有任何多余字符。

### 第三步：重启后端

**配置只在后端启动时读取一次**，改完 `.env` 必须重启后端才生效：

* 如果你是用 `./scripts/dev.sh` 启动的：在那个终端按 **Ctrl-C**，然后再跑一次 `./scripts/dev.sh`；
* 如果你是单独启动的后端：结束它再重新运行 uvicorn 命令。

前端**不需要**重启，也不需要任何配置——它永远不接触 Key。

### 第四步：验证（重要）

有两种方式，注意它们检查的东西不一样：

**① 界面上一键测试（推荐）**

打开 <http://localhost:3000>，在页面顶部会看到「测试 AI 连接」按钮，点一下：

* `✓ 连接正常，AI 解释已启用…` —— 说明密钥有效、网络通、模型名正确；
* `· 密钥无效（HTTP 401）。请确认…` —— 会直接告诉你下一步该检查什么。

这个按钮会**真实调用一次** DeepSeek（花费可以忽略），所以它的结论是可信的。

**② 命令行**

```bash
curl -X POST http://127.0.0.1:8000/api/llm/test
```

返回里的 `message_zh` 就是中文结论。

**注意区别**：`/api/health` 里的 `llm.available: true` 只表示"配置文件里填了 Key"，
**不代表 Key 能用**（填错了它也是 true）。真正的验证要靠上面两种方式。

### 怎么用上 AI 解释

配好之后不需要额外操作，打开复盘页里任意一个关键局面，解释区域就会自动变成「AI 教练解释」。
整盘总结也一样：在复盘页点「生成整盘总结」，就会用 AI 汇总这盘棋已经确认过的失误清单。

### 什么时候会调用、会花多少钱

* **分析棋局本身完全不调用 AI。** PGN 分析、关键局面挑选、概念检测全部在本机完成，
  所以复盘一盘棋的 AI 成本是 0。
* AI 解释是**懒加载**的：只有你点开某个关键局面（或点「生成整盘总结」）时才会调用一次。
* 生成过的解释会**按内容缓存**（键 = 局面 + 引擎证据 + 概念 + 决策分类 + 模型 + 提示词版本）。
  同一个局面再次打开会直接读缓存，不会重复花钱。
* 如果只是分析棋、不点开解释，一分钱都不会花。

### 换成其它 OpenAI 兼容服务

这套接口不绑定 DeepSeek。任何兼容 `/chat/completions` 的服务都能用，改两个变量即可：

```ini
# 例：换成别的服务商
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_BASE_URL=https://api.siliconflow.cn/v1
DEEPSEEK_MODEL=deepseek-ai/DeepSeek-V3
```

注意事项：

* `DEEPSEEK_BASE_URL` 只写到域名（或域名 + `/v1`），**不要**把 `/chat/completions` 写进去；
* 该服务需要支持 `response_format: {"type": "json_object"}`（结构化输出）。不支持的话，
  返回内容解析失败会退回到规则模板说明；
* 本地模型（如 Ollama）也可以：`DEEPSEEK_BASE_URL=http://127.0.0.1:11434/v1`，
  `DEEPSEEK_API_KEY=ollama`（随便填一个非空值），`DEEPSEEK_MODEL=你的模型名`。

### 如果失败了会怎样

**引擎复盘永远不受影响。** 所有失败情况（没配 Key、Key 无效、余额不足、超时、网络不通、
返回的 JSON 不合法、内容没有证据支撑）都只会导致同一件事：解释区域退回到规则模板说明，
并显示具体原因。当前端报告的原因包括：

| 界面提示 | 通常原因 |
| --- | --- |
| 密钥无效（HTTP 401） | 密钥复制不全、有空格换行、已过期或已删除 |
| 账户余额不足（HTTP 402） | DeepSeek 账户需要充值 |
| 请求超时 | 网络慢或需要代理，可调大 `.env` 里的 `LLM_TIMEOUT` |
| 网络连接失败 | 本机网络/代理问题；在 `.env` 里填 `HTTPS_PROXY=http://127.0.0.1:端口` 后重启后端 |
| 接口地址或模型名不对（404） | `DEEPSEEK_BASE_URL` 写成了完整路径，或模型名不受支持 |
| 返回内容不是合法 JSON | 服务商不支持 JSON 输出模式，或模型名不对 |
| AI 解释不可用（schema_validation_failed / grounding） | 模型返回内容缺字段，或编造了证据里没有的着法（会被直接丢弃） |

### 需要代理才能访问外网怎么办

在 `.env` 里加一行，然后重启后端：

```ini
HTTPS_PROXY=http://127.0.0.1:7890
```

后端启动时会把它导出成标准环境变量供 HTTP 客户端使用（shell 里已经存在的同名环境变量优先，
不会被覆盖）。填完记得用「测试 AI 连接」验证一次。

### 安全说明

* Key 只存在于后端进程的内存和后端读取的 `.env` 文件里；
* 前端代码里没有任何 Key，浏览器网络请求里也看不到它；
* `/api/health`、`/api/config`、`/api/llm/test` 这些接口只会返回"是否已配置"和模型名，
  **不会回显 Key 本身**；
* `.env` 已在 `.gitignore` 中，不会被提交。

## 4. 界面上哪些是"事实"，哪些是"解释"

这是这个项目最在意的一件事，所以界面上做了明确的区分：

| | 引擎证据（蓝框） | AI 教练解释（黄框） |
| --- | --- | --- |
| 来源 | 本机 Stockfish 原始输出 | 大模型根据左侧证据生成的中文 |
| 内容 | 评估、WDL、期望得分、推荐走法、PV 线路、其他候选 | 发生了什么、为什么重要、下次怎么想、可复用的经验 |
| 可信度 | 客观计算结果 | 只是**表述**，不产生任何新判断 |

任何时候你都可以展开「引擎证据」核对 AI 说的话。如果 AI 的输出没能通过校验（比如它编了一条
证据里不存在的线路），系统会直接丢弃这条 AI 解释，改成显示规则模板说明，并在下面注明原因——
宁可少一段文字，也不给你一段编造的分析。

### 严重程度怎么定

用的是**期望得分损失**，而不是评估分差：

```
期望得分 = 胜率 + 0.5 × 和棋率        （来自 Stockfish 的 WDL 数据）
损失     = 走最优着法时的期望得分 − 实战走法之后的期望得分
```

原因很简单：从 +0.3 掉 100 分和从 +9.0 掉 100 分是完全不同的两件事，而期望得分本身已经是
按人类对局结果标定过的。分类阈值全部集中在一个文件里（`backend/analysis/thresholds.py`）：

| 分类 | 期望得分损失 |
| --- | --- |
| 最佳 / 优秀 | ≤ 0.02（或者就是引擎的第一选择） |
| 良好 | ≤ 0.05 |
| 不够精确 | ≤ 0.10 |
| 失误 | ≤ 0.20 |
| 严重失误 | > 0.20 |

这些数字是**工程默认值，不是科学标定值**，想调直接改那一个文件。

  setup.sh      一次性安装

## 6. 全部配置项（`.env`）

复制 `.env.example` 为 `.env` 后按需修改。**所有变量都有默认值，不配置也能跑。**

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `STOCKFISH_PATH` | 自动查找 | 引擎路径。留空则先用 `backend/engine/bin/stockfish` |
| `STOCKFISH_THREADS` | 0（自动） | 0 = 用一半 CPU 核心，上限由 `ENGINE_MAX_THREADS` 控制 |
| `STOCKFISH_HASH_MB` | 64 | 引擎哈希表大小 |
| `PASS1_DEPTH` | 12 | 第一遍：扫描全部局面的深度 |
| `PASS2_DEPTH` | 18 | 第二遍：只分析关键局面的深度 |
| `PASS2_MULTIPV` | 3 | 关键局面保留几个候选着法 |
| `POSITION_TIMEOUT` | 25 | 单个局面的时间上限（秒） |
| `MAX_CRITICAL_MOMENTS` | 5 | 复盘页最多展示几个关键局面 |
| `DEEPSEEK_API_KEY` | 空 | **可选**。留空 = 只用规则模板说明（详见第 3 章） |
| `DEEPSEEK_BASE_URL` | api.deepseek.com | 任何兼容 OpenAI 协议的服务都可以 |
| `DEEPSEEK_MODEL` | deepseek-chat | 模型名 |
| `HTTPS_PROXY` | 空 | 需要代理才能访问外网时填，例如 `http://127.0.0.1:7890` |
| `HTTP_PROXY` | 空 | 同上，用于 http 请求 |
| `DATABASE_URL` | sqlite:///data/chess_coach.db | 相对路径基于 `backend/` 解析 |
| `CORS_ORIGINS` | localhost:3000,127.0.0.1:3000 | 允许访问后端的前端地址 |

### 关于端口

| 端口 | 谁在用 |
| --- | --- |
| **3000** | 本项目的界面（Next.js） |
| **8000** | 本项目的后端接口（FastAPI + Stockfish） |
| 3080 | DeepSeek Harness 自己的界面，**和本项目无关**，本项目不会占用它 |

想换端口：

```bash
BACKEND_PORT=8010 FRONTEND_PORT=3010 ./scripts/dev.sh
```

脚本会自动把前端指向新的后端地址，并把新的前端地址加入后端 CORS 白名单。

## 7. 常见问题

### 点了「开始分析」没反应，按钮写着「暂时无法分析」

说明前端连不上后端。页面顶部会有一条红色提示，里面写着当前在等哪个地址。
在项目根目录运行：

```bash
./scripts/dev.sh
```

它会把两个服务一起拉起来。只想单独启动后端：

```bash
cd backend && ../.venv/bin/python -m uvicorn api.main:app --port 8000
```

然后回到页面点「重试连接」。

### 启动前端时报：Another next dev server is already running

说明上次的 dev server 被强制结束（Ctrl-C 按了两次、终端被关掉、后台任务被回收），
Next.js 的锁文件 `.next/dev/lock` 留了下来。

**正常情况下你不需要管它**：`npm run dev` 现在会先运行
`frontend/scripts/reset-dev-lock.mjs`，自动判断锁里的进程是否还活着——
已经死了就自动清掉；还活着就用中文提示你「直接打开 http://localhost:3000，或者先 kill 那个 PID」。

如果提示里说进程还活着但你打不开页面，就按提示结束它再启动：

```bash
kill <提示里的 PID>
cd frontend && npm run dev
```

实在不行就把 `.next` 整个删掉重建（会慢一点）：

```bash
cd frontend && npm run dev:clean
```

### 端口被占用起不来

`dev.sh` 会先检查端口，被占用时会打印占用者的 PID 和三种处理方式。最省事的办法是换端口：

```bash
BACKEND_PORT=8010 FRONTEND_PORT=3010 ./scripts/dev.sh
```

### 提示找不到 Stockfish

```bash
.venv/bin/python backend/scripts/install_stockfish.py
```

或者装系统版（`brew install stockfish`）并在 `.env` 里写：

```
STOCKFISH_PATH=/opt/homebrew/bin/stockfish
```

改完重启后端。

### `npm install` 报 EPERM / 权限错误

说明 `~/.npm` 不可写（里面可能有 root 拥有的文件）。改用项目内的缓存目录：

```bash
cd frontend && npm install --cache ../.npm-cache
```

`setup.sh` 检测到这种情况会自动加上这个参数。

### 提示「PGN 无法解析」

本项目的解析是**严格**的：如果 PGN 只能被读出一部分，它宁可报错，也不分析一盘你没下过的棋。
常见原因：

* 复制不完整（少了几步、末尾的 `1-0` 被截掉后又接上了别的内容）；
* 一次粘贴了多盘棋：这时只分析**第一盘**，其余会被忽略；
* 走法本身不合法（例如同一方连走两步、走法被改过）。

如果一直失败，可以试试用「上传 PGN 文件」而不是粘贴。

### AI 解释一直显示「规则模板说明（未使用 AI）」

两种可能：

1. 没配 `DEEPSEEK_API_KEY` —— 这是完全支持的用法，不是故障；
2. 配了但调用失败（Key 无效、余额不足、超时、网络不通、返回内容不合格式）。

先点首页的「**测试 AI 连接**」按钮：它会真实调一次 DeepSeek，并用中文告诉你下一步该做什么。
完整配置步骤（放哪个文件、格式要求、如何验证、怎么换别的服务商）见
[第 3 章：配置 DeepSeek API Key](#3-配置-deepseek-api-key详细步骤)。

### 分析很慢

40 步左右的对局默认需要 10–30 秒。想更快可以调低 `PASS2_DEPTH` 或 `PASS1_DEPTH`；想更准就调高。
同一个局面分析过一次后会缓存下来，再打开这盘棋不会重新跑引擎。

## 8. 分析是怎么做的

### 两遍分析，因为引擎算力是最贵的资源

* **第一遍**：把整盘棋的**每一个**局面都便宜地扫一遍（`MultiPV=1`，默认深度 12）。
  由于每个局面只算一次，并且直接复用作下一步的"走子后"局面，期望得分损失几乎不额外花钱。
* **第二遍**：只对第一遍挑出来的关键局面做深入分析（默认深度 18，`MultiPV=3`），
  这样才能知道"次优选择是什么""这步好棋是不是唯一的"。算完之后用更深的数字**重新排序**。

每个局面的结果都会缓存（键 = FEN + 引擎 + 深度 + MultiPV + 线程 + 哈希 + 视角），
重开这盘棋不会重跑引擎；重新导入同一盘棋也会直接复用已有结果（除非请求里带 `force: true`）。

### 关键局面是怎么选出来的

综合下面这些信号加权排序（权重都在 `thresholds.py` 里）：期望得分损失、优劣反转、漏掉胜机、
杀棋出现/消失、胜负逆转、是否进入强制序列、好棋是否唯一。

**只有真的算得上问题的着法才会入选。** 一盘下得干净的棋会诚实地只显示少数几个（甚至零个）局面，
而不是硬凑成"4 个局面"。

### 概念检测：宁可不说，也不乱说

`backend/concepts/` 里有 27 个互相独立的检测器，每个都必须给出自己那条结论的证据：

* **具体战术**：悬子 / 无根子 / 被攻击的子力、丢子、漏吃、漏将、漏掉强制手、叉子、双重攻击、
  牵制、串击、闪击、防守子超载、引离、消除防守子、底线弱点、杀棋威胁、被困子力、
  中间着（过渡着）、交换弃子
* **局面性上下文**：王安全下降、兵形受损、孤兵、叠兵、通路兵、弱格、子力未展开、
  开局反复动后、子力活跃度、开放线/半开放线、双象、子力不平衡

每个检测器遵守的规则：

1. 只报告能写成"可核实证据"的结论；
2. 需要看后续才能成立的结论，必须用引擎自己的主变例来验证；
3. **沉默好过猜测** —— 界面上会写「没有检测到可靠的战术 motif」，而不是编一个出来；
4. 某个检测器出错时只记录日志并跳过，绝不拖垮整盘棋的分析。

### 从"棋盘上发生了什么"到"人哪里想错了"

`concepts/` 回答的是**发生了什么**（丢了一个象），`coaching/taxonomy.py` 回答的是**决策错在哪**
（移动防守子之前没有重新检查对手的强制手）。分类包括：未检查对手的强制手、移动/消除防守子后
出现战术漏洞、把子力放在会被直接吃掉的位置、忽略对手威胁、优势局面转换、开局出子等等。
每条规则有自己的置信度，一个着法可能同时命中几条；**一条都命中时，结论就是明确的"原因不明确"**，
而不是硬套一个听起来很专业的说法。

### 怎么防止 AI 胡说

模型只会收到一个 JSON 证据对象，并且必须按固定结构返回。在进入界面之前
（`coaching/grounding.py`）：

* 必须通过 `LLMExplanation` 的结构校验，否则直接丢弃，改用确定性说明；
* 事实性字段里出现的**任何着法**都必须在证据里存在（包括概念证据里的句子和这盘棋的历史着法）；
  凭空编出来的着法会让整条回复作废；
* 如果它把自己的建议说成"最佳走法"（例如「更好的走法是 X」），而 X 不在引擎给出的线路里，
  这条回复同样作废。只是提到对手的着法、或拿实战走法做对比（「引擎推荐 g6，而不是你走的 Nf6」），
  不受影响；
* 证据里没有的概念标签会被删掉，并作为警告显示出来；
* 置信度会被强制封顶（文字永远不等于证据）。

所有失败情况（没配 Key、超时、网络错误、JSON 不合法、结构不对、内容没有依据）最终都落到同一个
结果：**引擎复盘照常显示**，解释退回到确定性模板，并注明 AI 文字不可用。

## 10. 已知局限（写在前面，免得被误导）

* **严重程度阈值是工程默认值，不是标定过的科学结论。** 它们集中在一个文件里，方便按真实对局调整。
* **第一遍的深度可能看错一步棋。** 深度 12 会漏掉很深的战术；而深度分析只针对第一遍已经标记出来的
  着法。如果你看到明显不合理的分类，调高 `PASS1_DEPTH`。
* **多线程的 Stockfish 不是逐位可复现的。** `STOCKFISH_THREADS > 1` 时，同一盘棋两次分析的
  结果会有细微差别，处在阈值边缘的着法可能在相邻两档之间跳动。想要完全可复现就把
  `STOCKFISH_THREADS` 设为 1（会慢很多）；已经缓存过的局面则保持第一次的结果。
* **静态交换评估不考虑牵制**，所以偶尔会把一个实际上吃不掉的子标成"可以被吃"。
  它只是检测器的证据，最终判断始终以引擎线路为准。
* **被困子力和子力活跃度用的机动性是近似值**（基于攻击格计算，忽略牵制）。
* **阶段划分是启发式的**（子力 + 出子 + 回合数），只用于统计。
* **不分析时间压力。** 分类里有 `TIME_PRESSURE_UNKNOWN`，但目前没有规则会产生它：
  PGN 里的时钟注释还没有被解析。
* **`INTERMEDIATE_MOVE`（中间着）和 `EXCHANGE_SACRIFICE`（交换弃子）刻意做得很窄**，
  只在引擎线路真的出现该模式时才报告。
* **开局名来自 PGN 的 `[Opening]` 头或一张很小的对照表**，不是开局库。
* **同一时间只分析一盘棋。** 只有一个 Stockfish 进程，后面的任务排队。
* **个人档案是描述性的，不是诊断性的。** 少于 3 局 / 5 个失误时，界面只会说"目前观察到"，
  趋势图要 6 局以上才启用。
* **没有基于浏览器的自动化界面测试。** 前端靠类型检查、ESLint、生产构建、每个路由的服务端渲染
  冒烟检查，以及前后端字段契约脚本来保证；但没有跑过真实的浏览器自动化。

按需求明确**不做**的部分：账号系统、在线对战、社交功能、支付、云部署、开局库基础设施、
自研引擎、模型训练。
