# 分析工作台

打开一盘已复盘的棋谱，就能从任意局面试走。拖动，或点选起点和终点；落点提示遵守完整国际象棋规则，
包括王车易位、吃过路兵和四种升变。用「翻转棋盘」换视角。键盘也能在下方输入坐标走法，如 `e2e4`。

实战棋谱保留为主线。不同走法形成缩进分支，分支内还能继续分叉；点着法切换棋盘，三角按钮折叠变化。
从候选线上点某一步，会将到该步的整段变化加入棋谱。蓝色高亮标记当前着法，金色格子标记刚走的一步。
`←`、`→` 沿当前线路移动，`Home` 回起始局面，`End` 回实战终局；「回到实战分叉处」离开试走线路。

## 思考时间与资源

点引擎面板右上「设置」，修改后点「应用并重新分析」。选项只影响交互分析，整盘复盘的两遍分析预算仍由 `.env` 设置。

| 设置 | 行为 |
| --- | --- |
| 按时间 | 每个新局面计算指定秒数，0.1–600 秒 |
| 按深度 | 搜索至指定深度，1–60；耗时取决于局面、线程数和候选线数 |
| 持续分析 | 一直计算，直到暂停、换局面或离开页面 |
| Threads | Stockfish 线程数，1 到本机逻辑处理器数量（最多 64） |
| Hash（MB） | 置换表大小，16 到物理内存四分之一（最多 4096 MB） |
| MultiPV | 同时分析 1–5 条候选线路；线路越多，达到同样深度通常越慢 |

Hash 不是整个进程的内存上限。面板另外显示实际进程内存、Hash 使用比例、当前深度、计算速度和耗时。
实时分数固定为白方视角，正数白方有利，负数黑方有利；`M3` / `−M3` 分别表示白方 / 黑方有强制杀棋，
`≥` / `≤` 表示引擎尚未收敛的上下界。历史复盘证据仍明确使用其原来的棋手视角。

交互分析使用一个专用 Stockfish 进程，本机多个页面共用它；最新分析请求会停止前一个请求。
它与整盘复盘进程独立，若同时运行，两者的资源占用会相加。搜索传递完整走子历史，保留重复局面信息。
切换局面会停止旧计算、清除旧候选线；暂停或隐藏页面会停止计算，浏览器异常断开后约 15 秒自动停止。
本机 Stockfish 计算不产生 API 费用。Lichess 网络查询和可选 AI 教学解释仍是独立功能。

## 保存与恢复

分支自动保存到本机 SQLite，状态显示在棋谱底部。保存前浏览器会保留恢复草稿；数据库确认后移除草稿。
同一盘棋的多个页面若同时编辑，会显示版本冲突，保留当前草稿并允许导出；不会覆盖另一页面的修改。
有未保存的修改时先用「导出 PGN」备份，再刷新。若检测到不同版本的恢复草稿，会显示「导出草稿备份」。
浏览器禁止本地存储时无法保留离线草稿，界面会提示等待数据库保存或导出。每盘棋最多保存 2000 步（含变化）。

导出 PGN 包含当前页面的全部分支，即使保存失败也可导出。重新分析实战棋谱保留分支；删除整盘棋时一并删除分支。
这是单用户本地工具，没有面向公网的身份校验或用户隔离。Lichess 令牌仍只保存在忽略提交的后端目录。

## 接口与验证

`/api/analysis/options` 返回本机限额；`/api/analysis/start` 创建可取消的搜索；
`/api/analysis/{id}` 轮询当前结果并续期；`/api/analysis/{id}/stop` 停止该搜索。
`/api/games/{id}/study` 读取/按版本保存棋谱树；`/api/games/{id}/study.pgn` 导出已保存版本。
服务器独立验证局面、每一步合法性、树结构和主线完整性。

`backend/tests/test_workbench.py` 覆盖真实引擎预算、资源配置、取消与失联回收、终局、历史、分支、特殊走法、导出和版本冲突。
前端使用 chess.js 即时校验走法，浏览器体验测试另覆盖拖动、点选、嵌套变化、升变选择、刷新恢复、错误重试及手机布局。
